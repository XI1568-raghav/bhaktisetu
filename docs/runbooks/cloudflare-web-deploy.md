## Why "static" pages still hit error 1102 (measured 2026-10-22)
A prerendered page is NOT free if it is answered by the Worker. `.open-next/worker.js` does `await import("./server-functions/default/handler.mjs")` inside `fetch`, so the first request of every cold isolate pays the whole 45 MB server bundle init: **~0.9 s CPU measured** (workerd schedstat, `/refunds` cold) against the 10 ms limit. Warm static hits cost ~3 ms; an expired ISR page (`/darshan` had `revalidate` 30 s inherited from its API fetch, `/darshan/[id]` scraped youtube.com per render) costs 20-130 ms on top, because the read-only asset cache cannot store the regenerated page.
Fixes in place:
- `scripts/static-pages-to-assets.mjs` (run by `build:cf`, config `apps/web/scripts/cf-static-pages.json`) DISCOVERS routes from `.next/prerender-manifest.json` and copies the prerendered HTML into `.open-next/assets`: every fully static route (`initialRevalidateSeconds === false`: legal, support, darshan, all client portal/dashboard/profile/bookings/orders/admin shells, auth pages, ~517 pages) plus ISR routes under `isrStaticPrefixes` (committed-data sections such as aarti, chalisa, vrat, tirth; ~1078 pages; the Workers cache is read-only so they never refreshed anyway). Cloudflare answers them from the asset layer and never starts the Worker (cold request ~5 ms, was 0.9 s CPU). Opt-outs live in `exclude` (locale landings `/hi /ta /te /bn /mr`, `/help/articles/*`, `/_not-found`, `/static-shell/*`, `/og/*`). The build FAILS if a `mustBeStatic` route stops being fully static or a page under a `portalPrefixes` entry becomes non-static without a `workerServed` reason; `__tests__/cf-static-assets.test.ts` is the source-level guard (no `next/headers`, `cookies()`, `searchParams`, `revalidate` in portal/legal pages). Trade-offs for these paths: middleware does not run (no portal 307 for signed-out visitors, which AuthGuard + the API still enforce; no `?lang=`/locale-cookie handling; no `Content-Language` header; query strings and request headers are ignored), links to them do a full page load rather than an RSC soft navigation, and response headers come from `public/_headers` (CSP etc. are there; `/admin` noindex needed its own rule).
- `/darshan` and `/darshan/[id]` carry no `revalidate`; build-time data uses `getLiveDarshan({ buildTime: true })` (`force-cache`); live lists, the on-air probe and the IST-graded schedule load in the browser (`DarshanBrowserLive`, `DarshanChannelPlayerLive`, `DarshanAartiSchedule`, `DarshanScheduleTable`, `lib/darshan-client.ts`).
- `public/_redirects` maps `/refund-policy`, `/privacy-policy`, `/terms-of-service`, `/support/tickets/new` etc. to the real routes (the refund page is `/refunds`).
- Next 16.4.3 + `@opennextjs/cloudflare` 1.20.13 (2026-10-27): the `--dangerouslyUseUnsupportedNextVersion` flag is gone. `apps/web` builds with `next build --webpack` (the custom `webpack()` `extensionAlias` in `next.config.ts` makes a Turbopack build fail) and keeps `middleware.ts` (edge runtime; `proxy.ts` is Node-only and OpenNext would bundle it into the Worker). Measured locally on workerd: cold `/` ~1.4 s CPU on both Next 15 and 16 (the free-plan 10 ms limit is exceeded either way); Worker upload 52,674 KiB -> 46,156 KiB.
Update 2026-10-29 (measured with a local `opennextjs-cloudflare build` + `wrangler dev`; asset-served answers carry `Cache-Control: public, max-age=0, must-revalidate` and an ETag, Worker answers carry `s-maxage`/`no-store`): now asset-served as well, so no Worker start and no 1102: `/` (the `poojly_language` redirect is now `components/home/HomeLocaleRedirect.tsx`, an inline script with middleware's rules: bare root only, chosen supported locale only, query kept; the panchang chip and "What is coming up" resolve in the browser: `HomePanchangChip`, `ThisWeekLive`), the five locale landings and their subtrees (`/hi /ta /te /bn /mr`, `/ta/chennai`, ...: the cookie is written by the inline script in `app/layout.tsx`, `Content-Language` comes from `public/_headers`), `/temples` and `/temples/<slug>`, `/deity/*`, `/city/*`, `/puja/*`, `/blog*`, `/gaushala*`, `/wellness/vipassana|meditation|classes`, and `/admin/users/view?id=` (the admin user list now links there; `/admin/users/[id]` still works for old links but is Worker-served). ## CPU risk (free plan: 10 ms CPU per request)
Static/prerendered pages served from assets cost ~0 CPU. Risks:
1. `/og/puja/[slug]`, `/og/temple/[slug]`, `/og/shloka` (next/og, resvg wasm, Devanagari font fetch) cost >10 ms. **Mitigated (2026-10-17):** `pnpm build:cf` now runs `scripts/prerender-og.mjs` (via `scripts/build-cf.mjs`, under tsx) which writes ~100 PNGs to `apps/web/public/og/{puja,temple,shloka}/<slug>.png` (about 23 MB, so gitignored, never committed) and builds with `NEXT_PUBLIC_OG_STATIC=1`. With that flag `lib/og-static.ts` / `shlokaOgUrl` point `og:image` at the static files for every slug in the static data (temple-details, image catalog + home-pujas, SHLOKAS). Without the flag (Render Docker, `next build`, dev) nothing changes and the dynamic routes still serve. Slugs outside the static lists, API-only temples and the user-driven `/shloka-card` still hit the dynamic routes (expect CPU errors on Workers free; those requests only come from crawlers/share previews). Needs network for the font during `build:cf`; if unreachable the shloka cards are skipped. `pnpm prerender:og` renders the cards only.
2. Per-request SSR (build output marks them dynamic): `/pujas`, `/pujas/[slug]` (+book, temples), `/store`, `/astrology/[id]`, `/blog/[slug]`, `/panchang`, `/content`, `/deity/[slug]/mantras`, `/consultation/[id]`, `/donations`, `/wellness/classes/[id]`, `/yatra-packages/[slug]`, remaining `[slug]` pages without generateStaticParams. They fetch the API then render large trees; each is a candidate for 10 ms overruns. Mitigation: `generateStaticParams` + static data (done for 11), Cloudflare Cache Rules (edge cache on public GET pages, `s-maxage` is already set for /temples, /pujas, /yatra), or the Workers Paid plan ($5/mo, 30 s CPU) as the real fix.
3. `middleware.ts` runs on every page request (locale cookie + portal gate): small but it counts toward every request's CPU.
4. Free plan 100k requests/day applies to Worker invocations; assets served without the Worker do not count when `run_worker_first` is off (it is off in `wrangler.jsonc`).
Measure before cutover: Workers dashboard > Metrics > CPU time p99, using a `*.workers.dev` URL first.

### Edge cache (Cloudflare Cache Rules)
Workers use the static-assets incremental cache: prerendered pages are free, but on-demand ISR and any page reading `searchParams` render per request and Next marks the latter `private, no-store`. Code cannot fix that without touching `next.config.ts`, so cache at the edge. Dashboard > darshya.online > Caching > Cache Rules, create in this order (first match wins; use "Custom filter expression" > Edit expression):

1. **Bypass private/dynamic** - `(starts_with(http.request.uri.path, "/api")) or (starts_with(http.request.uri.path, "/auth")) or (starts_with(http.request.uri.path, "/admin")) or (starts_with(http.request.uri.path, "/dashboard")) or starts_with(http.request.uri.path, "/priest") or starts_with(http.request.uri.path, "/store-admin") or starts_with(http.request.uri.path, "/astrologer-portal") or starts_with(http.request.uri.path, "/wellness-portal") or starts_with(http.request.uri.path, "/gaushala-portal") or starts_with(http.request.uri.path, "/temple-portal") or starts_with(http.request.uri.path, "/payouts") or starts_with(http.request.uri.path, "/consultation") or starts_with(http.request.uri.path, "/store/cart") or starts_with(http.request.uri.path, "/store/checkout") or starts_with(http.request.uri.path, "/store/orders") or starts_with(http.request.uri.path, "/pujas/book") or starts_with(http.request.uri.path, "/donations")` -> Bypass cache.
2. **Bypass signed-in / non-default-locale visitors** - `(http.cookie contains "poojly_user") or (http.cookie contains "poojly_language") or (http.cookie contains "darshya_session") or (http.request.method ne "GET")` -> Bypass cache. (Public HTML varies on the locale cookie and middleware may Set-Cookie; this keeps one English anonymous copy cached, as `middleware.ts` intends.)
3. **Static assets** - `(starts_with(http.request.uri.path, "/_next/static")) or (starts_with(http.request.uri.path, "/images")) or (starts_with(http.request.uri.path, "/og/")) or (starts_with(http.request.uri.path, "/fonts"))` -> Eligible, Edge TTL 1 year, Browser TTL respect origin.
4. **Public content pages** - `(http.request.method eq "GET") and (starts_with(http.request.uri.path, "/temples") or starts_with(http.request.uri.path, "/pujas") or starts_with(http.request.uri.path, "/yatra") or starts_with(http.request.uri.path, "/blog") or starts_with(http.request.uri.path, "/deity") or starts_with(http.request.uri.path, "/panchang") or starts_with(http.request.uri.path, "/content") or starts_with(http.request.uri.path, "/store") or starts_with(http.request.uri.path, "/astrology") or starts_with(http.request.uri.path, "/wellness") or starts_with(http.request.uri.path, "/shlokas") or starts_with(http.request.uri.path, "/chants") or starts_with(http.request.uri.path, "/festival") or starts_with(http.request.uri.path, "/jyotirlinga"))` -> Eligible; Edge TTL: **Override origin**, 10 minutes (panchang: set a separate rule at 5 minutes); Browser TTL: respect origin; Serve stale while revalidating: on; cache key: include query string (default), do not ignore it (`/pujas?page=2`, `/content?type=`, `/store?filters` differ).
5. **Everything else** is left alone (default: HTML is not cached by Cloudflare).

Notes: rules 1 and 2 come first so they win over 4. `/store/cart|checkout|orders` are excluded in rule 1 even though rule 4 matches `/store`. Dynamic `/og/*` fallbacks and `/api/*` are never edge-cached with an override. Never use "Cache Everything" on a path that can render user data. After enabling, check `cf-cache-status: HIT` on `curl -sI https://darshya.online/pujas` twice, and confirm a request with `Cookie: poojly_user=x` shows `BYPASS`. Pages already given `revalidate` in code (`/pujas`, `/pujas/[slug]`, `/blog/[slug]`, `/deity/[slug]/mantras`, `/yatra-packages/[slug]`, `/wellness/classes/[id]`) emit `s-maxage` themselves; `/temples/:slug` and `/pujas/:slug` also get it from `next.config.ts`.

## Owner steps
1. Cloudflare dashboard > My Profile > API Tokens > Create Token > template "Edit Cloudflare Workers" (account scope = your account, zone scope = darshya.online). Copy the token. Account ID: dashboard > Workers & Pages sidebar (right panel) or the URL.
2. Locally (never commit these): `export CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=...`, plus the NEXT_PUBLIC_* values from the Render `darshya-web` env.
3. `cd apps/web && pnpm build:cf && pnpm preview:cf` - smoke `/`, `/jyotirlinga/somnath`, `/kundli` (308), `/robots.txt`.
4. Secrets: `cd apps/web && npx wrangler secret put GITHUB_TOKEN` (repeat per secret), or Dashboard > Workers > darshya-web > Settings > Variables and Secrets.
5. `pnpm deploy:cf` (first deploy creates the Worker at `darshya-web.<subdomain>.workers.dev`). Test it there fully (login, booking page, Razorpay checkout).
6. Custom domain: Dashboard > Workers > darshya-web > Settings > Domains & Routes > Add > Custom domain `darshya.online`, then `www.darshya.online`. Cloudflare replaces the existing proxied CNAME to `darshya-web.onrender.com` automatically; if it refuses, delete those two CNAME records first (this is the cutover moment, a few seconds of DNS change).
7. Verify prod, Search Console sitemap fetch, API CORS (API must allow the origin; unchanged host so no change expected).
8. Keep Render service `darshya-web` running for 48 h, then suspend.

## Rollback
Dashboard > Workers > darshya-web > Domains & Routes > remove both custom domains, then re-create DNS: `CNAME @ darshya-web.onrender.com` and `CNAME www darshya-web.onrender.com` (proxied, as in `docs/render-web-cutover-runbook.md`). Render was never stopped, so rollback is DNS-only. For a bad Worker version: `npx wrangler rollback` (or Dashboard > Deployments).
