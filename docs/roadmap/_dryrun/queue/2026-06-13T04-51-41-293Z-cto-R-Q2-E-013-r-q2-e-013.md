# R-Q2-E-013 — API rate limiting per-user + per-IP

caveman brief: cap requests. per-IP + per-user. block abusers.

## Pre-flight
1. `grep -r "rate-limit" apps/api/` — confirm if `@fastify/rate-limit` already registered.
2. Read `apps/api/src/server.ts` to find auth plugin (need user identity for per-user limit).
3. Check `apps/api/src/config/env.ts` (or equivalent) for env loading pattern.

## TDD step

Create `apps/api/test/security/rate-limit.test.ts`:
- 100 anonymous requests from same IP → 101st returns 429.
- authenticated user: stricter limit (e.g., 60/min per user across IPs).
- 429 response has `Retry-After` header.
- whitelist for health-check route (`/health`, `/ready`) — never limited.

`pnpm --filter @bhaktisetu/api test security/rate-limit` → FAIL red.

## Implementation

1. **Install if missing** — `pnpm --filter @bhaktisetu/api add @fastify/rate-limit`.
2. **Register** in server bootstrap:
   - global default: `max: 100, timeWindow: '1 minute'`, keyed by IP.
   - per-route override for `/api/auth/*`: tighter (e.g., 5/min).
   - per-user key: custom `keyGenerator: (req) => req.user?.id ?? req.ip`.
3. **Env config** — `RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW`, `RATE_LIMIT_AUTH_MAX` in env schema.
4. **Skip routes** — `allowList: ['/health', '/ready', '/metrics']`.
5. **Storage** — in-memory default; if Redis already in stack (`grep ioredis apps/api/package.json`), wire Redis store for multi-instance correctness. Else leave note in PR for future.
