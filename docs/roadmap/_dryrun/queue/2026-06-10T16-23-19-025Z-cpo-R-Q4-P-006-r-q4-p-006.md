## Deliverable structure

1. **Mission** — let temples run digital seva under own brand on our infra. Revenue: ₹15K/₹50K/₹2L per month per temple.
2. **Non-goals** — no per-tenant code forks, no custom features per tier-1 ticket, no white-label of antim sanskar v1 (dignity product stays Bhaktisetu-branded).
3. **Tenant data model** — `tenants` table:
   ```
   id uuid pk
   slug text unique (e.g., 'iskcon-mumbai')
   display_name text
   custom_domain text unique nullable (e.g., seva.iskconmumbai.org)
   subdomain text unique (e.g., iskcon-mumbai.bhaktisetu.com) — fallback
   plan_tier enum('starter','pro','enterprise')
   plan_started_at timestamptz
   plan_renewal_at timestamptz
   brand_primary_color text
   brand_logo_url text
   brand_favicon_url text
   brand_font_family text
   owner_user_id uuid fk users
   status enum('active','suspended','churned')
   created_at, updated_at
   ```
   Plus `tenant_members` (user_id, tenant_id, role enum('owner','admin','operator','viewer')), `tenant_settings` (kv json), `tenant_pricing_overrides` (puja_type_id, custom_price_inr).
4. **Tenant isolation strategy** — Supabase RLS policy template. Every tenant-scoped table gets `tenant_id` column + policy `tenant_id = current_setting('app.current_tenant_id')::uuid`. Document tenant context injection at API layer.
5. **Custom domain mapping (Cloudflare Pages)**:
   - Founder/ops adds custom domain in CF Pages dashboard
   - DNS CNAME instruction generated for temple admin
   - Middleware reads `Host` header → lookup `tenants.custom_domain` → set tenant context
   - Fallback: subdomain `<slug>.bhaktisetu.com` works out of box via wildcard
   - SSL: CF auto
   - Document edge case: domain pending verification → show neutral landing
6. **Brand asset upload**:
   - Logo, favicon → Supabase Storage bucket `tenant-brand-assets`, path `{tenant_id}/logo.{ext}`
   - Max 500KB per asset, PNG/SVG only, dimension limits
   - Color: hex validation, contrast ratio check vs white >= 4.5
   - Font: whitelist (Inter, Noto Sans Devanagari, Lora) — no arbitrary CSS upload
   - Preview screen before publish
7. **Role-scoped admin**:
   - `owner` — billing, plan change, member invite, brand, all data
   - `admin` — brand, members, all data, no billing
   - `operator` — booking management, no settings
   - `viewer` — read-only reports
   - Audit log table `tenant_audit_log` for all admin actions
8. **Pricing tiers** (founder confirms ₹):
   - **Starter ₹15K/mo** — subdomain only, 100 bookings/mo, basic brand (color+logo), 2 admin seats, email support
   - **Pro ₹50K/mo** — custom domain, 1000 bookings/mo, full brand, 10 seats, WhatsApp support, custom pricing overrides
   - **Enterprise ₹2L/mo** — unlimited, custom integrations slot (1 per quarter), 25 seats, dedicated ops contact, SLA 99.5%, custom contract
   - Annual prepay → 2 months free
   - Overage: ₹50/booking beyond cap
9. **5 wireframes ASCII**:
   - W1: Tenant admin dashboard (booking count, revenue MTD, member list)
   - W2: Brand settings page (color picker, logo upload, font select, live preview)
   - W3: Domain settings page (DNS instructions, verification status)
   - W4: Member management (invite, role assign, audit log)
   - W5: Public-facing themed booking page (showing tenant brand applied)
10. **Multi-tenant routing/middleware sketch** — pseudo-code for Next.js middleware:
    ```
    on request:
      host = req.headers.host
      tenant = lookup tenant by custom_domain = host OR subdomain match
      if not found → render bhaktisetu marketing
      set tenant_context cookie / header
      set RLS session var
    ```
11. **Migration plan from current single-tenant** — add `tenant_id` column to existing booking/order tables, default to `bhaktisetu-internal` tenant uuid, then enforce NOT NULL. Document phased rollout.
12. **Security checklist** — RLS verified per table, no cross-tenant queries possible from API, brand assets served with `tenant_id` path check, custom domain verification prevents takeover, role escalation prevented.
13. **Success criteria** (verbatim):
    - Populate during first sub-agent emission cycle
    (Add: CSAT 90% temple admin, zero cross-tenant data leaks in pen test, custom domain provisioning <24h)
14. **Open questions for founder** — confirm pricing, GST handling per tenant, invoice format white-label or Bhaktisetu-branded?, who owns customer data legally?, kill-switch policy on payment default.
