## Implementation steps

### 1. DB migration
- Create `supabase/migrations/<timestamp>_cs_macros_v2_post_booking_intents.sql`
- INSERT 10 intents × 6 langs = 60 rows. EN + HI = full content. ta/te/bn/mr = stub with `body='TODO: pending R-Q2-CS-003 native review'` + `status='pending_native_review'`.
- Schema check: if `cs_macros` lacks `status` or `lang` cols, ADD them.
- 10 intent_keys: `refund`, `reschedule`, `pandit_no_show`, `language_mismatch`, `payment_failed`, `otp_missed`, `nri_timezone`, `gift_booking`, `group_booking`, `kyc`

### 2. Macro content (EN + HI)
Write actual helpful copy. Example shape for `refund` EN:
```
Hi {{name}}, refund for booking {{booking_id}} is processed within 5-7 working days to original payment method. Track status: bhaktisetu.com/booking/{{booking_id}}. Reply HUMAN if you need assistance.
```
HI equivalent for each. Include `{{escalation_trigger}}` for `pandit_no_show` + `payment_failed` (force human handoff).

### 3. WA webhook intent matcher
- File: locate WA webhook handler. Add `matchIntent(message, lang)` fn.
- Use simple keyword + regex matcher (NO LLM yet — that's later cycle). Score per intent. Top score >0.7 → return macro. Else return null → existing escalation path fires.
- Log every match attempt to `cs_bot_interactions` table (create if missing: id, message_id, matched_intent, confidence, resolved_auto BOOLEAN, ts).

### 4. Playbook doc
- Output: `docs/agent-reports/cs/wa-bot-v2-auto-resolve-playbook.md`
- Sections: intent list + trigger keywords (EN+HI), escalation thresholds, KPI query for `wa_bot_auto_resolve_pct`, runbook for adding new intents, native-review TODO checklist for ta/te/bn/mr (blocks).

### 5. KPI query
Populate the TBD in roadmap item:
```sql
SELECT
  COUNT(*) FILTER (WHERE resolved_auto) * 100.0 / NULLIF(COUNT(*),0) AS wa_bot_auto_resolve_pct
FROM cs_bot_interactions
WHERE ts >= NOW() - INTERVAL '30 days';
```
Update item file `kpi.query` with this.
