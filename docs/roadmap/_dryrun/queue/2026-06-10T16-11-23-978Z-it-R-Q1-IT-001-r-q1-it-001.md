## TDD approach (infra item — verify-first, not test-first)

No pnpm tests for SaaS config. Verification is curl-based.

### Pre-create verify (sanity check endpoints respond before pointing monitors)

```bash
curl -sS -o /dev/null -w "%{http_code}\n" https://api.darshya.online/health
curl -sS https://api.darshya.online/health | grep -o '"ok"' || echo "MISSING ok keyword"
curl -sS -o /dev/null -w "%{http_code}\n" https://darshya.online
curl -sS -o /dev/null -w "%{http_code}\n" https://api.darshya.online/api/v1/temples
```

All four must return 200 / `ok` keyword before creating monitors. If any fail, STOP and escalate — monitors will instantly alert.

### Post-create verify

```bash
# After monitor IDs known, hit UptimeRobot API to confirm status
curl -X POST https://api.uptimerobot.com/v2/getMonitors \
  -d "api_key=$UPTIMEROBOT_API_KEY" \
  -d "format=json" \
  -d "monitors=<id1>-<id2>-<id3>"
```

Expect all 3 in `status: 2` (Up) within 10 min.
