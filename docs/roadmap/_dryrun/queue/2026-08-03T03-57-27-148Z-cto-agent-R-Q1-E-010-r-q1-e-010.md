# R-Q1-E-010 — Astrologer slug to UUID design pass + migration

## Goal
Astrologer table currently uses slug as lookup key. Migrate to UUID PK with slug retained as unique index. Update FK references. Update API + web routes to accept both slug + uuid for backward compat.

## Files to touch (cite line numbers on edit)
- `prisma/schema.prisma` — Astrologer model block. Add `id String @id @default(uuid())` (or `@db.Uuid`). Demote `slug` from `@id` to `@unique`. Update AstrologerConsultation.astrologerId + AstrologerAvailability.astrologerId FK types from slug-string to uuid-string.
- `apps/api/src/routes/astrology.ts` — astrologer lookup. Currently: `prisma.astrologer.findUnique({ where: { slug } })`. Change to: try `findUnique({ where: { id } })` first (if input matches UUID regex `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i`), else fall back to `findUnique({ where: { slug } })`.
- `apps/web/app/astrology/[id]/page.tsx` — dynamic route. The `[id]` param now accepts either slug or uuid. No structural change needed (route already polymorphic) — but verify getStaticParams / generateStaticParams if SSG; may need to add `fallback: 'blocking'` if not already.

## Migration plan (founder MUST review)
1. Author Prisma migration: `pnpm --filter api prisma migrate dev --name astrologer_uuid_pk --create-only` (creates SQL, does NOT apply)
2. Inspect generated SQL at `apps/api/prisma/migrations/<timestamp>_astrologer_uuid_pk/migration.sql`. Verify:
   - ADD COLUMN id UUID DEFAULT gen_random_uuid() (or `@default(uuid())` app-side — pick one; prefer DB-side for atomicity)
   - BACKFILL: UPDATE "Astrologer" SET id = gen_random_uuid() WHERE id IS NULL (only if DB-side)
   - DROP existing PK constraint on slug
   - ALTER TABLE ADD PRIMARY KEY (id)
   - CREATE UNIQUE INDEX ON "Astrologer"(slug)
   - ALTER "AstrologerConsultation" ALTER COLUMN astrologerId TYPE uuid USING astrologerId::uuid (only safe if existing values are uuids — if they're slugs, need a JOIN backfill: `UPDATE AstrologerConsultation ac SET astrologerId = (SELECT id FROM Astrologer a WHERE a.slug = ac.astrologerId)`)
   - Same for AstrologerAvailability
3. Run migration + backfill on STAGING first. Run orphan-check tests.
4. Founder-action: deploy to prod via `pnpm prisma migrate deploy` (NOT `migrate dev`).
5. Redeploy Render api service.
6. Smoke test prod endpoints.

## Backfill safety
- BEFORE migration: `SELECT slug, COUNT(*) FROM "Astrologer" GROUP BY slug HAVING COUNT(*) > 1;` — must be zero. If non-zero, halt: slug collision makes unique-index demotion impossible without dedup.
- BEFORE migration: `SELECT COUNT(*) FROM "AstrologerConsultation" WHERE astrologerId NOT IN (SELECT slug FROM "Astrologer");` — orphan count. Must be zero or you'll lose FK integrity. Same for Availability.
