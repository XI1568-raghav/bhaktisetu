## Concrete success criteria (CTO-defined, founder approve in handoff)
- Any of devotee/temple/pandit can open dispute via `/disputes/<bookingId>` within 30 days of booking completion
- Opening dispute transitions booking to `disputed` state; funds frozen in escrow_holds
- 3-way thread: each party adds evidence (text + image upload via Supabase storage, free tier)
- Admin arbitrates within 72h; ruling triggers refund (or partial) + reputation adjustment
- KPI: ≥90% of disputes ruled within 72h, rolling 30d
- WA notifications fire on: open, evidence-added, ruling-issued
- Audit log immutable (append-only table w/ row-level lock)

## Updated kpi.query (write to item file)
```sql
SELECT
  ROUND(
    100.0 * SUM(CASE WHEN EXTRACT(EPOCH FROM (resolved_at - opened_at))/3600 <= 72 THEN 1 ELSE 0 END)
    / NULLIF(COUNT(*),0)
  , 2) AS pct
FROM disputes
WHERE status = 'resolved'
  AND opened_at >= NOW() - INTERVAL '30 days';
```
