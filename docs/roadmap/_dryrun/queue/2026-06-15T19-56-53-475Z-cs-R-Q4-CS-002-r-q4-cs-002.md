# Q4-CS-002 — Automated Tier-3 Escalation (AI triage + auto-route + founder escape)

## Caveman context
Tier-3 = donor-impact, refund disputes, deity-image errors, legal/compliance.
Build AI triage that classifies inbound ticket → routes to right specialist →
escalates to founder if confidence low OR keywords critical (legal, refund>₹5k, press, safety).

Free-tier: no paid LLM. Use rule-based classifier + Supabase pgvector embeddings
(local model via @xenova/transformers — already in stack per prior CS work; verify).

### 3. Triage classifier lib
File: `apps/api/src/lib/cs-triage.ts`
```ts
export type Tier = 1 | 2 | 3;
export interface TriageResult {
  tier: Tier;
  confidence: number; // 0-1
  reason: string;
  keywordsMatched: string[];
  escalateToFounder: boolean;
  assignedSpecialist: string | null;
}
export async function triageTicket(subject: string, body: string, donorMetadata?: {ltvInr?: number}): Promise<TriageResult>
```
Logic:
- Rule layer: keyword regex per tier (legal, refund, press, deity, safety, GDPR, RBI)
- Embedding layer (if @xenova available): cosine-sim to seed examples per tier
- Confidence = max(rule_score, embedding_score)
- `escalateToFounder = true` IF tier===3 AND (confidence<0.7 OR keywords include legal|press|safety|refund≥5k)
- Specialist routing: refund→finance-specialist, deity-image→content-lead, legal→founder, press→founder

TDD `apps/api/src/lib/__tests__/cs-triage.test.ts`:
- "I need a receipt" → tier 1, high conf
- "Refund my ₹500 donation" → tier 2
- "Refund my ₹50000 donation, threatening legal action" → tier 3, escalate founder
- "Wrong photo of Krishna shown on receipt" → tier 3, content-lead
- Ambiguous "hello" → low conf, default tier 2 for human review

### 4. Auto-route endpoint
File: `apps/api/src/routes/cs-triage.ts`
- POST `/cs/triage` body `{ticketId}` → runs triage, updates ticket, writes audit, sends notification
- If `escalateToFounder` → send via founder escape-hatch channel (configurable env `FOUNDER_ESCAPE_CHANNEL=email|whatsapp|sms`, fallback email to `FOUNDER_EMAIL`)
- Feature flag `cs_tier3_auto_escalation` — if off, only writes triage_tier, no auto-notify

### 5. Founder escape hatch
File: `apps/api/src/lib/founder-escape.ts`
- `notifyFounder(ticket, triage): Promise<void>`
- Free-tier: email via Resend free tier OR Supabase Edge Function with SMTP env vars
- Payload: ticket subject, donor name, amount if refund, triage reason, direct link to admin UI
- Idempotent: don't double-notify same ticket within 1h (check `escalated_to_founder_at`)

TDD: mock transport, assert called once with right payload, assert idempotency.

### 6. KPI endpoint
File: `apps/api/src/routes/cs-triage-kpi.ts` GET `/cs/triage/kpi`
```sql
SELECT
  COUNT(*) FILTER (WHERE triage_tier = 3 AND assigned_specialist IS NOT NULL)::float
  / NULLIF(COUNT(*) FILTER (WHERE triage_tier = 3), 0) * 100 AS tier3_auto_escalation_pct,
  COUNT(*) FILTER (WHERE triage_tier = 3) AS tier3_count,
  COUNT(*) FILTER (WHERE escalated_to_founder_at IS NOT NULL) AS founder_escapes_count
FROM cs_tickets
WHERE created_at >= now() - interval '30 days';
```
