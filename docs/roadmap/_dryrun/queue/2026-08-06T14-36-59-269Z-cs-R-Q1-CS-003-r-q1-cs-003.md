## STEP 2: BUILD CHURN DETECTION SCRIPT (TDD)

Create: `apps/api/scripts/ops/churn-signal-detector.ts`
Test: `apps/api/scripts/ops/__tests__/churn-signal-detector.test.ts`

Purpose: read bookings + devotee activity, flag users showing churn signals. Prioritizes interview recruitment + winback outreach. EN-only CSV output. NOT a Wati template. NOT multilingual.

**Write tests FIRST** (per superpowers doctrine). 12 tests minimum:

1. Empty bookings input → empty CSV with header only
2. Single booking, no churn signals → not flagged (excluded from output)
3. Single booking, SLA breach in past → flagged, signal `sla_breach`, severity low
4. Repeat SLA breaches (2+) → flagged, signal `repeat_sla_breach`, severity high
5. No repeat booking after 30 days from first → flagged, signal `no_repeat_booking_30d`, severity low
6. No repeat booking after 60 days → severity medium
7. No repeat booking after 90 days → severity high
8. User with cancelled booking → flagged, signal `cancellation`, severity low
9. Multiple churn signals → all listed (pipe-separated in CSV), severity = max of signals
10. CSV field escaping (commas, quotes, newlines in devotee name) — wrap in quotes, escape inner quotes
11. Sort determinism: by severity desc (high>medium>low), then daysSinceLastBooking desc, then devoteeId asc
12. Idempotency: same input → same output byte-for-byte (stable sort, no Date.now() in output)

Then implement `churn-signal-detector.ts`:

- Read from `/admin/ops/bookings` endpoint (same source as `sla-breach-outreach.ts`). Accept `ADMIN_OPS_TOKEN` env var.
- For each devotee with >=1 booking in past 90 days:
  - Compute `daysSinceLastBooking` (UTC, not local tz)
  - Check SLA breach history (reuse logic from `sla-breach-outreach.ts` — extract shared helper if needed, else duplicate with test)
  - Check cancellation count
  - Compute `churnSignals` array
  - Compute `severity` (low/medium/high) from signal count + signal types
- Output CSV columns: `devoteeId,name,phone,daysSinceLastBooking,lastBookingId,churnSignals,severity,suggestedAction`
  - `churnSignals` = pipe-separated list
  - `suggestedAction` values: `interview_invite` (severity high), `winback_outreach` (medium), `monitor` (low)
- Write CSV to stdout (founder redirects to file). Do not write files directly.
