## step 2 — author spec

target ~600-800 LOC. structure:

### 1. User Journey (linear narrative + flow diagram)
couple/parent enters wedding date+city → 
  (a) muhurat calc — auto-suggest top 3 dates within ±15 days using existing panchang engine; show shubh/ashubh badges + reasoning (tithi, nakshatra, yoga)
  (b) venue suggestions — filter by city, capacity (50/200/500/1000+), budget bracket, veg-only kitchen yes/no, parking, AC, in-house decor; show 5-8 per query
  (c) pandit dispatch — match pandit by sampradaya (Smarta/Vaishnava/Arya Samaj/regional), language, fee bracket; book slot
  (d) vendor checklist — catering (per-plate ₹400-₹2500), photographer (₹50K-₹5L bracket), mehndi artist (₹5K-₹50K), decor, baraat band, makeup, invitations
  (e) progress dashboard — couple sees % complete, T-minus countdown, payment timeline

### 2. Data Model Deltas (SQL)
```sql
CREATE TABLE wedding_event (
  id uuid PK,
  couple_primary_user_id uuid FK users,
  couple_secondary_name text,
  wedding_date date,
  ceremony_type text CHECK (...),  -- engagement/haldi/mehndi/sangeet/main/reception
  city text, venue_id uuid FK venues NULL,
  muhurat_id uuid FK muhurat_request NULL,
  guest_count_estimate int,
  budget_total_inr int,
  package_tier text,  -- silver/gold/platinum
  status text,
  created_at, updated_at
);

CREATE TABLE wedding_vendor_booking (
  id uuid PK,
  wedding_event_id uuid FK,
  vendor_category text,  -- catering/photo/mehndi/decor/band/makeup
  vendor_id uuid FK vendors,
  quoted_amount_inr int,
  paid_amount_inr int,
  status text,  -- inquiry/quoted/booked/cancelled/completed
  contract_doc_url text,
  created_at, updated_at
);

CREATE TABLE muhurat_request (
  id uuid PK,
  wedding_event_id uuid FK NULL,  -- nullable, can pre-exist
  requested_window_start date,
  requested_window_end date,
  city text, lat numeric, lng numeric,
  computed_options jsonb,  -- top 3 dates w/ scoring
  selected_option_idx int,
  computed_at timestamptz,
  pandit_reviewer_id uuid FK pandits NULL  -- optional manual override
);
```

### 3. API Surface (8-12 endpoints)
```
- `POST /api/wedding/events` — create event
- `GET /api/wedding/events/:id` — read with nested vendor bookings
- `PATCH /api/wedding/events/:id` — update budget/guest count/status
- `POST /api/wedding/muhurat` — compute muhurat options for date window + city
- `POST /api/wedding/muhurat/:id/select` — lock selected muhurat option
- `GET /api/wedding/venues` — search venues with filters
- `POST /api/wedding/vendor-bookings` — create vendor inquiry
- `PATCH /api/wedding/vendor-bookings/:id` — vendor accepts/quotes
- `POST /api/wedding/vendor-bookings/:id/confirm` — couple confirms + pays advance
- `POST /api/wedding/pandit-match` — request pandit assignment
- `GET /api/wedding/checklist/:eventId` — derived checklist with completion %
- `POST /api/wedding/packages/quote` — generate package quote (silver/gold/platinum)
```

### 5. Revenue Model
package tiers table:
| Tier | Price | Includes | Margin |
|------|-------|----------|--------|
| Silver | ₹15,000 | muhurat + pandit + checklist tool | 60% |
| Gold | ₹50,000 | + venue assist + 3 vendor intros | 35% |
| Platinum | ₹2,00,000 | + dedicated wedding manager + full vendor suite | 20% |

take rate on vendor bookings: 8% (catering/decor) - 12% (photographer/makeup). transparent — disclosed to vendor + couple.

unit economics worked example: avg gold customer → ₹50K package + ₹3L vendor GMV @ 10% = ₹80K revenue. CAC target ₹8K. payback 1 booking.
