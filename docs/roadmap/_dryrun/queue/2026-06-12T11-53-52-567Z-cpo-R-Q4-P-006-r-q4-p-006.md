## Required H2 sections (13, in order)

1. **Problem** — why temples need white-label. Cite pain (generic Darshya branding kills diocese trust). 1 short para + 3-bullet pain list.
2. **Personas** — three tables, one each:
   - Temple admin (single temple, e.g. ISKCON Bangalore)
   - Diocese ops (regional, e.g. ISKCON South India)
   - Chain HQ (national, e.g. ISKCON GBC / BAPS HQ / Sringeri Math)
   Each table: goals, tech sophistication, daily workflow, pricing sensitivity.
3. **User journeys** — 3 numbered journeys (one per persona). Step-by-step from signup → first booking on white-label domain.
4. **Custom-domain architecture** — diagram in mermaid:
   - Tenant adds CNAME `bookings.iskconbangalore.org → tenant-iskcon-blr.darshya.online`
   - Cloudflare Pages multi-tenant routing via `Host` header
   - Fallback: if CNAME not configured, serve at `iskcon-blr.darshya.online`
   - SSL: CF auto-provisions via SNI
   - Cite CF Pages multi-domain docs URL
5. **Branding system** — propose `tenant_config` table:
   ```
   tenant_config (
     tenant_id PK,
     logo_url, primary_color, accent_color,
     hero_headline, hero_subtext,
     favicon_url, og_image_url,
     custom_css TEXT NULL,
     created_at, updated_at
   )
   ```
   Specify: admin uploads via signed S3/R2 URLs. Validation: hex colors only, logo ≤500KB PNG/SVG.
6. **Multi-tenant admin** — tenant scoping strategy:
   - Prisma middleware injects `WHERE tenant_id = $current` on every query (cite middleware pattern, link to existing if any)
   - Fastify auth hook validates JWT `tenant_id` claim, attaches to request context
   - RLS-like guards: any query missing tenant filter → throw `MissingTenantScopeError` (fail closed)
   - Cite exact file paths where engineering must add: `apps/api/src/plugins/auth.ts:<line>` and `packages/db/src/middleware/tenant-scope.ts` (new file)
7. **Pricing tiers** — table:
   | Tier | Price/mo | Bookings cap | Custom domain | Branded email | SLA | Support |
   |---|---|---|---|---|---|---|
   | Starter | ₹15K | 500 | subdomain only | no | 99.0% | email 48h |
   | Growth | ₹50K | 2,500 | yes | yes | 99.5% | email 24h |
   | Enterprise | ₹2L | unlimited | yes + multi-domain | yes | 99.9% | phone + slack |
8. **Onboarding flow** — 7-step checklist for new tenant. Include: KYC docs, GST, bank account, DNS setup, branding upload, test booking, go-live.
9. **Data isolation guarantees** — explicit statements:
   - Row-level: tenant_id on every table (list which tables; cross-ref schema)
   - Storage: tenant-prefixed S3/R2 keys
   - Logs: tenant_id in every structured log entry
   - Backups: per-tenant export capability
   - Cross-tenant leak = P0 incident
10. **SLA** — uptime per tier (above), incident response times, credit policy (e.g. 10% credit per 0.1% miss), maintenance windows.
11. **Open questions** — ≤10 bullets, each founder-decidable in <5min. Examples to seed:
    - White-label mobile app or web-only v1?
    - Allow tenant to override transactional email sender domain (DKIM setup burden)?
    - Per-tenant Razorpay sub-merchant or platform-collect-then-payout?
    - Anchor partner discount: 50% off year 1?
12. **Success metrics** — copy from item kpi (whitelabel_temple_csat ≥90%). Add: # tenants onboarded by end Q4 (target 3), domain provisioning p95 <10min, branding upload-to-live <2min.
13. **Out of scope v1** — explicit list: mobile app, multi-language admin UI, white-label SMS sender ID, custom payment gateway per tenant, marketplace features, donor CRM export to tenant's Salesforce.
