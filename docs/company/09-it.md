## 1. Today's incident-response capability — true state

**Alert paths**: Sentry → email (default project notification) → founder inbox. That is the only wire. There is no PagerDuty, no Slack webhook, no SMS, no second pair of eyes. PostHog and Cloudflare Web Analytics are dashboards — they do not page anyone. Render's "deploy failed" mail goes to the owner email. Supabase outages surface only when the API starts 500-ing and Sentry catches the exception (`server.setErrorHandler` in `apps/api/src/server.ts:133` forwards to `captureException`).

**On-call rotation**: founder, only, 24/7, untracked. No backup, no escalation. If founder's phone is on silent during a 02:00 outage, the site is down until morning.

**Runbook freshness**: there is no runbook. `docs/launch-state.md` is a status board, not a procedure. `docs/security-pass-2026-04-27.md` is an audit, not a playbook. The closest thing to "what do I do when X breaks" is the env-var contract in `docs/env-vars.md` (read it — it answers half the "is the integration down or off?" questions).

**Honest score: 3 / 10.** We capture errors (good), we route them to a human (good), the human is the only human (bad), the human has no playbook (bad), and we cannot detect a hard down — Sentry only sees the API's own errors, not "the API is unreachable." A 6 needs uptime monitoring + a one-page runbook + a documented backup pager (a friend, a partner — anyone). A 9 needs a real rotation, which we do not have headcount for.

## 3. The 5 things most likely to break in the next 30 days

1. **Render free-tier hibernation kills cold starts** — instances spin down after 15 min idle; first request after sleep takes 30-60s. **Detection**: UptimeRobot 5-min ping keeps it warm *and* alerts on >10s response. **Mitigation**: the ping itself is the warm-up; the cron job (`daily-cron.yml`, 00:00 UTC) is a second heartbeat. If we outgrow this, $7/mo Render Starter removes hibernation — that's the first paid line item I will defend.
2. **Supabase pooler connection-limit exhaustion** — free tier caps direct connections; Prisma without pgBouncer leaks under load. **Detection**: Sentry will catch `PrismaClientInitializationError: too many connections`. **Mitigation**: ensure `DATABASE_URL` uses the pooled port (6543) not direct (5432); set Prisma `connection_limit=1` for serverless-style invocations. Verify before launch traffic.
3. **Cohere monthly free quota exhaustion** — embeddings power semantic search; free tier is generous but finite (1K calls/min trial, then capped). **Detection**: 429s in `lib/embeddings.ts` will surface as Sentry events. **Mitigation**: code already falls back to LIKE matching when `COHERE_API_KEY` is absent — extend to also fall back on 429. Pre-compute embeddings for static catalog (temples, pujas) so live queries are user-text only.
4. **Render free instance-hours / Supabase Storage bandwidth** — *(corrected 2026-09-02, `OPS-10`; this item used to read "Cloudflare Pages build minutes … Pages free is 500 builds/mo … Pages → Analytics." There is no Pages project and therefore no Pages build quota — Pages stopped serving the web tier at the 2026-07-08 cutover.)* The real ceiling is Render's **750 free instance-hours per account, not per service**: `bhaktisetu` (API, `render.yaml:12`) and `darshya-web` (`render.yaml:53`) both run always-on and need ~1,488 h between them, which is what suspended the account on 2026-08-17. Supabase Storage free is 1GB storage + 2GB egress/mo, and video proof of pujas is the high-bandwidth user data. **Detection**: Render dashboard → Billing → instance-hours used this cycle; Supabase dashboard → Storage usage. **Mitigation**: budget a paid Render tier for at least one of the two services — this is not an optional line item; cap upload size at 25MB (already in plan). For now, watch instance-hours and egress weekly.
5. **Razorpay webhook signature drift** — the `RAZORPAY_VERIFY_RAW=true` flag (security pass #1) is gated; if Razorpay rotates payload formatting, the legacy `JSON.stringify` path silently passes/fails wrong. **Detection**: payment success rate in PostHog vs. Razorpay dashboard divergence. **Mitigation**: flip the flag in test mode, run `docs/razorpay-webhook-test.md`, ship the raw-bytes verifier to prod within the month.

## 4. Backup posture

- **Postgres / Supabase**: free tier provides daily automatic backups with 7-day retention [VERIFY — Supabase docs have moved this between free and paid; confirm in dashboard → Database → Backups]. Point-in-time recovery is paid only. We have no off-site copy.
- **User-uploaded video proof of pujas** lives in Supabase Storage bucket `darshya-media` (see `docs/launch-state.md` — the R2 swap). Storage objects are NOT covered by Supabase's DB backup; they are a separate S3-compatible store with no automatic versioning on free tier. **This is the most important user data we hold and it has zero redundancy today.**
- **Code**: GitHub is the source of truth. Three remotes is enough.
- **Secrets**: Render env vars + GitHub Actions secrets. No exported snapshot. If the Render account is locked, every key (Supabase service-role, Razorpay, Cohere, VAPID, magic-link secret) is recoverable only by re-issuing.

**Action items**: (a) export `pg_dump` weekly to a local encrypted folder until we can afford R2/B2 cold storage; (b) enable Supabase Storage object-level versioning if/when paid tier is reached; (c) keep an offline copy of the secrets list in a password manager.

## Single biggest IT risk

**Single-operator on-call with no uptime monitoring and zero off-site backup of puja-video proof.** The product's core trust promise is "we filmed your puja and you can watch it" — and that file lives in one Supabase Storage bucket on a free tier with no replication, behind an API whose only outage detector is the founder happening to look at the site. If Supabase has a regional incident at 03:00 IST and a single video is corrupted, we cannot prove the puja happened, the booking is a refund, and the brand promise breaks publicly. Fixing the monitoring (UptimeRobot, 30 minutes of work) and the backup (weekly Storage object export to local disk, 1 hour of work) costs nothing and removes more risk than any other action on this list.
