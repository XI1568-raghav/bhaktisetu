# W1 — apps/web Responsive-Design Audit

**Scope:** `apps/web` (Next.js 15 App Router + Tailwind v4, ~390 page routes).
**Method:** static source recon — grep sweeps + targeted reads. No browser run; every
measurement below is arithmetic on the declared Tailwind classes, not a screenshot.
**Viewports considered:** 320 / 360 / 375 / 390 / 414 (phone), 768 / 820 / 1024 (tablet), 1280 / 1536 / 1920 (desktop).
**Date:** 2026-09-02

> Established before this audit and NOT re-verified here: root viewport meta is
> `width=device-width, initial-scale=1` with no `maximum-scale` lock; production returns HTTP 200.

## Severity key and counts

| Severity | Meaning | Count |
|---|---|---|
| **P0** | Blocks a user action, or the page is unusable / content unrecoverable on a common device | **4** |
| **P1** | Visibly broken layout — overflow, clipping, unreadable squeeze, sub-44px control in a money path | **14** |
| **P2** | Polish — touch targets, missing truncate, cosmetic reflow, low-traffic routes | **13** entries covering ~190 individual sites |

**Headline:** the codebase is unusually disciplined about responsive layout — the
homepage, `/pujas`, `/store`, `/darshan`, both checkouts, all 8 portal shells and every
portal data table carry deliberate, commented breakpoint work. The damage is concentrated
in **four systemic overlay/breakpoint bugs**, not in the page bodies.

## Already good — do not spend fix effort here

These patterns were checked and are correct. Several carry measurement comments in-source
showing the breakpoint was reasoned about rather than guessed.

- **Portal shells (all 8).** `app/{admin,priest,astrologer-portal,wellness-portal,temple-portal,gaushala-portal,store-admin}/layout.tsx` share one well-built shell: `fixed lg:sticky ... w-64` sidebar that slides with `-translate-x-full lg:translate-x-0`, an `lg:hidden` scrim, an `lg:hidden` hamburger, `min-w-0` on the content column, and `p-4 lg:p-6` on `<main>`. Sidebars **do** collapse on mobile. Only the `<nav>`-scroll and touch-target nits above apply.
- **`components/SiteChrome.tsx`.** Explicitly strips the consumer header and bottom tab bar on portal routes (RESP-10) and drops the corresponding `pt-16 pb-20` offsets — the triple-chrome stacking bug is already fixed, with safe-area handling.
- **Portal data tables.** `app/priest/payouts/page.tsx:319`, `app/store-admin/products/page.tsx:532`, `app/temple-portal/donations/page.tsx:179` and `app/darshan/page.tsx:375` all use the correct `hidden md:grid grid-cols-12` desktop row **plus a dedicated mobile card variant** (`md:hidden space-y-2`), with `min-w-0` + `truncate` on the text cells. This is the reference pattern to copy for the P1 tables above.
- **Admin tables.** ~36 of the 53 `<table>` elements already sit inside `overflow-x-auto` wrappers.
- **Portal stat grids.** Every dashboard uses `grid-cols-2 lg:grid-cols-4` or `grid-cols-1 sm:grid-cols-3` — all reflow correctly at 320px.
- **`components/Inbox.tsx:211-213`.** Proper master/detail: `grid-cols-1 md:grid-cols-[320px_1fr]` with `hidden md:flex` on the list when a thread is open, and a `md:hidden` back button at `:555`.
- **`components/CategoryNav.tsx:299-300`.** Mega-menu panels use `w-[min(1120px,calc(100vw-48px))] max-h-[min(720px,calc(100vh-120px))] overflow-y-auto` — viewport-relative in both axes. `CategoryMegaMenu`/`LibraryMegaPanel`'s `grid-cols-4` is safe precisely because it only ever renders inside this desktop-only tree.
- **`components/LiveChatWidget.tsx:205`.** The open chat panel is `w-[360px] max-w-[calc(100vw-24px)] h-[540px] max-h-[calc(100vh-40px)]` — correctly capped. Only the launcher (P0 above) is misplaced.
- **`components/GlobalSearch.tsx:269,304`.** Full-screen overlay below `sm:`, anchored 420px popover above it, results capped at `max-h-[60vh] overflow-y-auto`.
- **`components/MobileNavV2.tsx`.** Aside from the breakpoint bug, this is a genuinely complete mobile nav: full category tree (5 accordions over `CATEGORY_TREE`), auth-aware account links, help links, in-sheet search, a sticky "Ask Pandit" CTA, `min-h-[44px]` on **every** link and accordion trigger, body scroll-lock, `inert` background, focus trap and focus restore. No top-level destination is missing from it. *(Two gaps worth noting rather than fixing blind: the guest branch offers "Sign In" but no explicit "Sign Up", and `ListYourBusinessDropdown` has no drawer equivalent — supply-side entry is header-only and therefore desktop-only.)*
- **`components/MobileBottomTabs.tsx`.** 4 tabs, `h-14` full-height hit areas, `env(safe-area-inset-bottom)`, and it already offsets itself above the consent banner via `--consent-h`. Suppressed on `/auth/*` and `/checkout/*` so it never fights a form CTA.
