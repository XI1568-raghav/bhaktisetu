# ISKCON Partnership — Letter of Intent (LOI) Template v1

> **Purpose**: starting point for ISKCON central deal OR multi-temple bundle LOI. NOT a signed agreement — LOI is non-binding intent to negotiate a full MoU.
>
> **Authoring date**: 2026-06-12 · **Reviewers needed before send**: founder + Bhaktisetu Foundation counsel + any senior advisor.
>
> **Important**: LOI is intentionally short (~2 pages). Long LOIs read as MoUs and trigger procurement-level scrutiny prematurely. Goal of an LOI = get to a "yes, let's negotiate" conversation, not lock terms.

## Companion notes (NOT part of LOI — remove before send)

### When to send

- ONLY after a verbal "yes, send formal LOI" via cold-email/WA outreach (`iskcon-outreach-kit-v1.md`). Sending cold LOI as first contact reads as transactional and damages relationship.

### Customisation per recipient

| Recipient | Tweak |
|---|---|
| Bureau Secretary | §1.2 references "ISKCON Bureau (India)" + §2.1 lists indicative 5 temples to be selected jointly |
| Individual TP (pilot) | §1.2 references only that specific temple + §2.1 N=1 |
| Regional secretary (zonal bundle) | §1.2 references zone + §2.1 lists 3-5 temples in zone |

### Counsel review checklist

- [ ] CIN + MCA reg # filled correctly
- [ ] §2.2 commercial split confirmed against Bhaktisetu economics model
- [ ] §6 jurisdiction clause aligned with Foundation registration city
- [ ] §1.3 "Adopt-a-Temple" tier reference removed if not yet shipped at time of send
- [ ] No promises of exclusivity in §3 — keep both parties non-exclusive during pilot

### LOI vs MoU

This is LOI (intent). After mutual go-ahead, draft full MoU with:
- Specific temple names + puja types
- Commercial split per puja type
- IP licensing (ISKCON name + logo usage)
- Donor data handling (DPDPA)
- Termination clauses
- Indemnity + insurance
- Dispute resolution mechanism (mediation → arbitration → court)
- Counterparty due-diligence checklist signed

Don't conflate. LOI is the door-opener. MoU is the deal.
